# Portfolio rules

- Prioritize credibility, usability, accessibility,
  performance, and maintainability.
- Keep dependencies minimal.
- Never invent personal or professional facts.
- Reuse existing components and design tokens.
- Prefer Server Components unless interaction requires
  a Client Component.
- Read only relevant files for each task.
- Make the smallest coherent change.
- Do not rewrite unrelated files or dump entire files
  into chat.
- Use official documentation when API behavior is
  uncertain.
- Verify changes using actual available checks.
- Report changed files, checks, failures, and the next
  useful action concisely.
